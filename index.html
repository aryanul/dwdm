Data Warehousing

What is a Data Warehouse?

A regular database is like a cashier's register — handles quick, live, day-to-day transactions. A data warehouse is like a giant library archive — it stores years of clean, organized historical data specifically for analysis and reporting.

Key properties remembered by the acronym SITN: Subject-oriented · Integrated · Time-variant · Non-volatile
  • Subject-oriented: Organized around business topics (Sales, HR, Finance) — not around applications
  • Integrated: Data from many sources (CRM, ERP, web logs) is unified and cleaned into one consistent format
  • Time-variant: Keeps historical snapshots with timestamps — you can analyse 5-year trends, not just today's data
  • Non-volatile: Once data is loaded, it is never updated or deleted — it's read-only for analysis

Fact Table

The central table in any data warehouse schema. Stores measurable, quantitative business events — the "what happened" numbers you want to analyse.

Example: A Sales Fact table stores quantity_sold, revenue, discount_amount for every single transaction.

Contains: Measures (the numbers you analyse) + Foreign keys that link to dimension tables.

Typically very large — millions to billions of rows.

Dimension Table

Provides the context around the facts — answers "who, what, where, when." Think of dimensions as the labels and filters for your facts.

Example: A Time dimension → day, month, quarter, year. A Product dimension → product_name, category, brand, price.

These are what you "group by" or "filter by" in analysis queries. Dimensions describe the facts.

Typically small — hundreds to thousands of rows.

Data Cube

A multi-dimensional view of data. Imagine a Rubik's cube where each axis is a dimension (Time, Product, Region) and each cell holds a measure value (Total Sales Amount). A data cube generalises this to any number of dimensions.

3D Data Cube: [Year × Product × Region]

Each cell = Total Sales for that combination
Cell (2024, Laptop, West Bengal) = ₹50 Lakh
Cell (2023, Phone, Maharashtra) = ₹82 Lakh

You can slice, rotate, or summarize this cube in many ways — that is exactly what OLAP operations do.

Star Schema ⭐

The simplest, most popular schema. One central fact table connects directly to multiple dimension tables — looks like a star shape when drawn.

  • Fast queries — fewer joins needed
  • Some data redundancy in dimension tables
  • Easier to understand and use
  • Most common in real-world data warehouses
Fact_Sales → DimTime, DimProduct, DimStore (all direct connections)

Snowflake Schema ❄️

An extension of the Star Schema where dimension tables are normalized into sub-dimension tables — creating a snowflake-like branching structure.

  • Eliminates redundancy → saves storage
  • More complex joins → slightly slower queries
  • Harder to understand but more organized
  • Better for write-heavy scenarios
DimProduct → DimCategory → DimDepartment (chained, normalized tables)

ETL Process — Extract, Transform, Load

The pipeline that moves raw data from source systems into the data warehouse. Think: making juice — pick fruit (Extract) → wash, peel, blend (Transform) → pour into bottle (Load).

E

Extract — Pull raw data from source systems: relational databases, APIs, spreadsheets, flat files, logs. Data at this stage may be messy, inconsistent, or in different formats.

T

Transform — Clean, validate, and reshape the data: handle null values, remove duplicates, standardize date/currency formats, encode categorical variables, join tables, compute derived fields, apply business rules.

L

Load — Insert the clean, transformed data into the data warehouse. Usually done in scheduled batches (nightly or weekly), not in real-time.

Common transformations: null handling, deduplication, date format standardization (DD/MM/YYYY → YYYY-MM-DD), currency conversion, unit standardization (kg vs lbs), encoding categoricals (Male/Female → 0/1).
ETL runs on a schedule, so your warehouse may be 1 day behind live data. That's perfectly acceptable for analytics — you're not booking tickets, you're analysing trends.

Data Preprocessing

Why Preprocessing?

Real-world data is messy — it has missing values, outliers, inconsistencies, and features at vastly different scales. Preprocessing cleans and prepares data before any mining algorithm is applied.

The golden rule of data science: Garbage In = Garbage Out. The best algorithm applied to bad data gives bad results. Preprocessing is what turns dirty data into clean, usable data.

Smoothing Noisy Data

Noise = random errors, typos, or outliers in your data. There are three main smoothing techniques you need to know for your exam:

1. Binning — The most exam-important technique. Sort data, divide into equal bins, then smooth each bin by replacing values with the bin's mean, median, or boundary values.

Raw sorted data:  4, 8, 15, 21, 24, 25
Divide into bins of size 3:
  Bin 1 = [4, 8, 15]
  Bin 2 = [21, 24, 25]

Smooth by Mean (replace each value with bin mean):
  Bin 1 mean = (4+8+15)/3 = 9   → [9, 9, 9]
  Bin 2 mean = (21+24+25)/3 = 23.3 → [23.3, 23.3, 23.3]

Smooth by Boundary (replace each value with nearest boundary):
  Bin 1 boundaries = 4 and 15
  4 → 4 (already the boundary)
  8 → 4 (closer to 4 than to 15, distance 4 vs 7)
  15 → 15 (the boundary itself)

2. Regression — Fit a regression curve through the data. Values are replaced by their prediction on the curve, smoothing out random fluctuations.

3. Clustering / Outlier removal — Group data into clusters. Points that fall far from any cluster are identified as outliers and removed or treated separately.

For exams: Binning is the most commonly asked technique. Know the steps cold: Sort → Partition into bins → Smooth by mean/median/boundary.

Data Integration

Combining data from multiple, heterogeneous sources into one unified, consistent store. This is harder than it sounds because different sources use different naming conventions, formats, and scales.

  • Schema conflicts: Source A calls it "customer_age", Source B calls it "age_years" — same concept, different names
  • Value conflicts: Source A uses kg, Source B uses lbs for weight — same concept, different units
  • Redundancy: "annual_income" in one source and "yearly_earnings" in another — detect using correlation
  • Entity resolution: Is "J. Smith, 12 Park St" the same person as "John Smith, 12 Park Street"? Resolving this is critical.
Integration builds a consistent, unified view — a prerequisite before any meaningful data mining can happen.

Discretization

Converting continuous (numeric) values into discrete categories (intervals/bins). Makes data compatible with algorithms that prefer or require categorical input (like Naive Bayes or Decision Trees).

Age (continuous): 17, 22, 35, 48, 62, 71

Discretized into categories:
  Young  = 0–30  → 17, 22
  Middle = 31–60 → 35, 48
  Old    = 61+   → 62, 71

Output (categorical): Young, Young, Middle, Middle, Old, Old
Real-life example: instead of storing exact exam marks (78.5, 91.2...), you assign a letter grade (B, A+...). That's discretization.

Normalization — Why it matters & How to do it

When features have very different scales (CGPA: 5–10 vs Assessment marks: 30–100), algorithms like KNN and SVM get biased toward the larger-scale feature, because distances are dominated by it. Normalization brings all features to the same scale.

Min-Max Normalization → maps everything to [0, 1]

x' = (x - x_min) / (x_max - x_min)

Example: Height = 170 cm, min=150, max=190
x' = (170-150) / (190-150)
   = 20 / 40
   = 0.5  (exactly in the middle)
Sensitive to outliers. One extreme value compresses everything else into a tiny range.

Z-Score Normalization (Standardization) → mean=0, std deviation=1

x' = (x - μ) / σ
μ = mean of the dataset
σ = standard deviation

Example: x=80, μ=70, σ=10
z = (80-70)/10 = +1.0
(1 std dev above the average)
More robust to outliers. Preferred when data follows a normal distribution. Values can be negative or above 1.

OLAP Operations — Imagine a Sales Cube [Year × Product × City]

Roll-Up (Drill-Up) — Summarize by moving UP the hierarchy. Reduces detail, increases aggregation.

Day → Month → Quarter → Year. You're "zooming out" to see the big picture.

Drill-Down — The reverse of Roll-Up. Navigate from summary to more granular detail.

Year → Quarter → Month → Day. You're "zooming in" to investigate why something happened.

Slice — Fix ONE dimension to a specific single value. Produces a 2D flat cut of the cube.

Slice: Year = 2024
→ 2D table: Product × City, for 2024 only
(the "2023" and other year layers are removed)

Dice — Fix MULTIPLE dimensions to ranges of values. Produces a smaller 3D sub-cube.

Dice: Year ∈ {2023, 2024}
      City ∈ {Delhi, Mumbai, Kolkata}
→ A smaller sub-cube with only those values

Pivot (Rotate) — Rotate the axes to get a different perspective. Like transposing a matrix.

Switch from "Products as rows, Cities as columns" → "Cities as rows, Products as columns." Same data, different view.
Memory trick: Slice = 1 fixed dimension | Dice = multiple fixed dimensions | Roll-up = aggregate upward | Drill-down = disaggregate downward

Data Mining

The process of automatically discovering patterns, rules, and insights from large datasets using statistical and machine learning algorithms. It's the core analytical engine inside the KDD process.

Classification: Predict which predefined category a new item belongs to. (KNN, Naive Bayes, SVM, Decision Tree)

Clustering: Group similar items together without any predefined labels. (K-Means, DBSCAN)

Association: Find items that frequently co-occur — "if A then often B." (Apriori, FP-Growth)

Regression: Predict a continuous numeric value. (Linear Regression, Logistic Regression)

Association Rules & Apriori Algorithm

Market Basket Analysis — the core idea

A supermarket analyses thousands of receipts to find patterns like "customers who buy bread also tend to buy butter." These patterns are expressed as association rules and can drive product placement, promotions, and recommendations.

The most famous real-world finding: Walmart discovered that customers who buy diapers on Friday evenings also tend to buy beer. They placed the products near each other → sales increased for both. Association rules can reveal non-obvious, surprising patterns.

Support

Measures how frequently an itemset appears across all transactions. Filters out rare, statistically insignificant combinations.

Support({X, Y}) =
  # transactions containing BOTH X and Y
  ─────────────────────────────────────
        Total number of transactions

If {Bread, Juice} appears in 3 of 5 txns:
Support = 3/5 = 60%
The min_support threshold ensures we only focus on combinations that appear often enough to be meaningful and actionable.

Confidence

Given that X is purchased, how likely is Y also purchased? Measures the reliability or strength of the rule X → Y.

Confidence(X → Y) =
  Support(X ∪ Y)      [itemset containing both]
  ──────────────
    Support(X)         [itemset containing X]

If Bread appears in 4 txns and {Bread,Juice} in 3:
Confidence(Bread→Juice) = 3/4 = 75%
High confidence means the rule is reliable, but it does NOT mean causation — it's correlation. People don't buy beer because of diapers; they're just correlated.

Frequent Itemset & Association Rule

Frequent Itemset: An itemset whose support meets or exceeds min_support. Only these are considered for rule generation.

min_support = 50% (need count ≥ 3 of 5 txns)

{Bread}: 4 txns → 80% → Frequent ✓
{Milk}: 3 txns → 60% → Frequent ✓
{Egg}: 1 txn → 20% → NOT frequent ✗
{Bread, Juice}: 3 txns → 60% → Frequent ✓
{Egg, Milk}: 1 txn → 20% → NOT frequent ✗

Association Rule: An implication of the form X → Y, meaning "if a customer buys X, they also tend to buy Y." Generated from frequent itemsets with high enough confidence.

Format: LHS (antecedent) → RHS (consequent) | support, confidence
Example: {Bread} → {Juice} | sup=60%, conf=75%
Only frequent itemsets generate rules. This is why we compute support first and then confidence.

The Apriori Principle — Why it works efficiently

The key insight that makes Apriori tractable on large datasets: "If an itemset is infrequent, ALL of its supersets must also be infrequent."

If {Egg} has support 20% (below min_support = 50%):
  → {Egg, Bread} is DEFINITELY below 50% ✗
  → {Egg, Milk, Bread} is DEFINITELY below 50% ✗
  → {Egg, Milk, Bread, Juice} is DEFINITELY below 50% ✗

We prune ALL supersets of {Egg} without even checking them!
This is called the anti-monotone property. Instead of checking all 2^n possible itemsets (exponential), Apriori prunes the search space dramatically — it's why the algorithm is practical on real data.

Decision Tree & Gini Index

A Decision Tree is a flowchart-like structure where each internal node tests a feature, each branch is an outcome, and each leaf node is a class label. The tree learns which questions to ask in which order to classify data.

Like 20 Questions: "CGPA > 7.0? → Yes. Assessment > 65? → Yes. → Predict: Pass." Each question splits the data, making each group purer.

Gini Index measures how "impure" or mixed a node is. The algorithm chooses splits that minimize Gini.

Gini = 1 - Σ(pᵢ²)   where pᵢ = proportion of each class

Pure node (all Pass, no Fail):
  Gini = 1 - (1.0² + 0.0²) = 0  ← perfect purity

Completely mixed node (50-50 split):
  Gini = 1 - (0.5² + 0.5²) = 1 - 0.5 = 0.5 ← worst case

Node with 3 Pass, 2 Fail (p = 3/5 = 0.6 and 2/5 = 0.4):
  Gini = 1 - (0.6² + 0.4²)
       = 1 - (0.36 + 0.16)
       = 1 - 0.52 = 0.48
When deciding which feature to split on, compute the weighted Gini for each candidate split. Choose the feature that gives the lowest weighted Gini (equivalently, highest Information Gain). This is how the tree "learns" which questions to ask first.

KNN — K-Nearest Neighbors Algorithm

To classify a new data point, find the K most similar training points (by Euclidean distance) and take a majority vote of their class labels. Simple, intuitive, and surprisingly effective.

Analogy: You move to a new city and want to know if your new neighborhood is good. You ask your K nearest neighbors about it and go with the majority opinion.
Euclidean distance (3 features):
d = √[(x₁-x₂)² + (y₁-y₂)² + (z₁-z₂)²]

Example: test=(7.6,60,8), training=(9.2,85,8)
d = √[(9.2-7.6)² + (85-60)² + (8-8)²]
  = √[2.56 + 625 + 0]
  = √627.56 ≈ 25.05

Steps:

  • Calculate distance from test point to every training point
  • Sort distances in ascending order (nearest first)
  • Select the top K nearest training points
  • Count the majority class among those K neighbors
  • Assign that majority class to the test point
Small K (e.g., K=1): Very sensitive to noise and outliers. The decision boundary is very jagged.
Large K: Smoother decision boundary, but may miss local patterns. Captures the global structure better.
Always use odd K for binary classification to avoid ties (e.g., K=3 not K=4).
KNN is a "lazy learner" — it doesn't build an explicit model during training. It just memorizes all training data and computes at prediction time. Simple but can be slow for large datasets.

Naïve Bayes Classifier

Uses Bayes' Theorem with the "naïve" assumption that all features are statistically independent given the class label. Despite this often unrealistic assumption, it works remarkably well in practice.

Bayes' Theorem:
P(Class | Features) ∝ P(Class) × ΠP(Featureᵢ | Class)

For each candidate class, compute:
  Prior probability × Product of all likelihoods

Pick the class with the HIGHEST score.
  • P(Class): Prior — how often does this class appear overall?
  • P(Featureᵢ | Class): Likelihood — how often does this feature value appear for this class?
Think of it as: "I see evidence X and Y. Which hypothesis — Pass or Fail — makes this evidence most likely?"

Works great for categorical data and text classification (spam detection, sentiment analysis).

The "naïve" assumption: features are treated as independent. In reality, "Confident" and "Studied" might be correlated. Naive Bayes ignores this — but it still gives good results in many practical cases.

SVM — Support Vector Machine

SVM finds the best hyperplane that separates classes with the maximum margin. In 2D, the hyperplane is a line. In 3D, it's a plane. In higher dimensions, it's called a hyperplane.

  • Hyperplane: The decision boundary that separates classes. Points on one side = Class A; points on other side = Class B.
  • Margin: The distance between the hyperplane and the nearest training points on each side. SVM maximizes this margin.
  • Support vectors: The data points closest to the hyperplane. They "support" or define the position and orientation of the hyperplane — if you removed all other points, the hyperplane would stay the same.
  • Kernel trick: Projects data into a higher-dimensional space where it becomes linearly separable, then finds the hyperplane there. Useful when data cannot be separated by a straight line in its original space.
Imagine drawing the fattest possible straight line between two groups of scattered points. The fatter the line (larger margin), the more confident and robust your classifier is — it can tolerate more noise.
SVM maximizes the margin → less overfitting, more robust than just finding any separating line. Especially powerful in high-dimensional spaces (like text classification).

K-Means — Centroid-based Clustering

Partitions n data points into K clusters. Each cluster is represented by its centroid (the geometric center/mean of all points in that cluster). Points are assigned to the cluster of the nearest centroid.

Called "centroid-based" because:

  • Every cluster is defined by its centroid (the average position of all its points)
  • Assignment is based on distance to centroids, not to individual points
  • Centroids are recomputed after every assignment step

Algorithm:

1

Choose K initial centroids (randomly or as given in exam)

2

Assign each point to the nearest centroid (using Euclidean distance)

3

Recompute each centroid = mean of all points currently assigned to it

4

Repeat steps 2–3 until centroids stop changing (convergence)

Advantages: customer segmentation, anomaly detection, document organization, image compression, data summarization before supervised learning.

DBSCAN — Density-Based Spatial Clustering

Finds clusters of arbitrary shape (not just spherical like K-Means) based on the density of points. Does not require specifying K — discovers the number of clusters automatically.

Two key parameters: ε (epsilon) = neighborhood radius | MinPts = minimum neighbors required

Three types of points:

  • Core point: Has at least MinPts data points within radius ε. It's a "popular" point at the dense center of a cluster.
  • Border point: Falls within ε of a core point, but has fewer than MinPts in its own neighborhood. It's on the edge of a cluster.
  • Noise point (outlier): Not reachable from any core point. Doesn't belong to any cluster.
Party analogy: Core point = popular person surrounded by many friends. Border point = their acquaintance on the edge of the group. Noise = a stranger who knows nobody.
Key advantages over K-Means:
1. Handles non-spherical cluster shapes (crescents, rings, irregular blobs)
2. Automatically identifies outliers as noise
3. Doesn't require K to be specified upfront
4. Less sensitive to initialization
Downside: Requires careful tuning of ε and MinPts. Can struggle when clusters have varying densities.

Regression

Simple Linear Regression

Models the linear relationship between one independent variable (X) and one continuous dependent variable (Y). Fits the best straight line through the data that minimizes prediction errors.

Equation:  y = a + bx

Slope (b) — how much Y changes per unit X:
b = (nΣXY − ΣXΣY) / (nΣX² − (ΣX)²)

Intercept (a) — value of Y when X = 0:
a = (ΣY − b·ΣX) / n
  • Slope (b): Positive b = upward trend (more study → better marks). Negative b = downward trend.
  • Intercept (a): Where the best-fit line crosses the Y-axis. The baseline value.
Example: If b=5 for study hours → exam marks, each extra hour of study is predicted to add 5 marks.

Exam Q7 — Internal → External marks (n=15 students):

Given: ΣX=299, ΣY=852, n=15
       ΣXY=17413, ΣX²=6187

Step 1 — compute slope b:
b = (15×17413 − 299×852)
    ÷ (15×6187 − 299²)
  = (261195 − 254748)
    ÷ (92805 − 89401)
  = 6447 ÷ 3404
  ≈ 1.89

Step 2 — compute intercept a:
a = (852 − 1.89×299) / 15
  = (852 − 565.1) / 15
  ≈ 19.06

Final equation: y ≈ 19.06 + 1.89x

Predict external marks for internal = 20:
y = 19.06 + 1.89×20 = 19.06 + 37.8 = 56.9

Multiple Linear Regression

Extends simple linear regression to multiple independent variables. More realistic — real outcomes depend on many factors simultaneously.

y = a + b₁x₁ + b₂x₂ + b₃x₃ + ... + bₙxₙ
Example: House price (Y) predicted from:
x₁ = size (sq ft), x₂ = number of bedrooms, x₃ = distance from city center
y = 50000 + 150×(size) + 20000×(bedrooms) − 1000×(distance)
  • Dependent variable (Y): The outcome you predict. Depends on other variables. (House price, exam score, revenue)
  • Independent variables (X): The inputs you observe or control. Predict Y. (Size, study hours, CGPA, temperature)
  • Each bᵢ = change in Y for 1-unit increase in xᵢ, holding all other variables constant
  • More features = better fit, but risk overfitting if too many features for too few data points
  • Multicollinearity: Problem when two X variables are highly correlated with each other — makes bᵢ unstable and hard to interpret
With many features and limited data, use Ridge or Lasso regularization to prevent overfitting.

  P(Confident=Yes | Pass) = 2/3 ≈ 0.667
  Fail rows = rows 1, 3 → Confident values: Yes, No → 1 "Yes" out of 2
  P(Confident=Yes | Fail) = 1/2 = 0.500

Step 3 — Likelihoods for "Sick = No":
  Pass rows Sick values: Yes (row2), No (row4), Yes (row5) → 1 "No" out of 3
  P(Sick=No | Pass) = 1/3 ≈ 0.333
  Fail rows Sick values: No (row1), Yes (row3) → 1 "No" out of 2
  P(Sick=No | Fail) = 1/2 = 0.500

Step 4 — Multiply (prior × likelihoods for each class):
  Score(Pass) = 0.600 × 0.667 × 0.333 = 0.133
  Score(Fail) = 0.400 × 0.500 × 0.500 = 0.100

0.133 > 0.100 → Prediction: PASS

Note: Studied is not given in the query, so we only use Confident and Sick as features. The naïve assumption means we can safely ignore the missing feature.
